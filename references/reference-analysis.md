# 已保存的风格与参考使用规则

## 两种模式

**日常生产**只读本规范及现有assets模板，不再取回、渲染或逐页观察曾分析过的参考PDF。具体样式问题无法由本规范解决，或用户明确要求时，才看相关页，并将得到的改进写回规范/模板。

**首次建风格、更换参考或明确复刻**才运行inspect_pdf.py，完整提取文本、检查全部缩略图并放大关键页。提炼信息组织和视觉参数，保存后日常复用；不复制原稿公司、观点、评级、阈值、来源名录、页数或机构署名。若只是从参考中读本期线索，按普通研究来源处理相关内容，不重新做样式逆向。

本风格已经从参考TMT周报中提炼并保存。团队分发只包含下列规范和通用模板，不包含私人参考原件、作者聊天记录或其转述数据；内置example-report.json为合成演示。新使用者可直接复用、改进规范，无需找回开发者参考稿。

## 日常信息组织与写作

- 先让读者看到本期研究主线和重要变化，再给证据、解释、市场反应、投资含义及验证条件；按问题选择需要的部分，不逐页套固定段落。
- 标题优先主体＋事件＋关键数字/变化；判断性标题需有证据。正文解释数字改变哪个变量，不复述图上所有数据；事实、自报、预测、观点与推断可辨认。
- 一页回答一个清楚的问题；重大主题可由事实/驱动、竞争解释、定价与验证等多个页面展开。小事件可合并，重复删去，不按原稿章节权重或页数裁剪。
- 有依据的图表优先展示核心变量；数值充分不默认表格。同指标、分母、单位和期间先核对，稀疏数据不补连续趋势。图与文字互相解释，不用装饰图或多指标混排充数。
- 图文分析可用左图约58%／右解释约42%；总览、对照表、复盘与日历使用适合内容的布局。每页底部以投资观点、研究判断或后续观察收束，具体深度由研究决定。

## 视觉参数与实现

| 项目 | 已保存规范 |
|---|---|
| 舞台 | 1920×1080，16:9整体缩放；屏幕操作栏放舞台外预留区，不盖正文/引用；打印一页一张，隐藏控件 |
| 字体 | 正文/标题优先本地Noto Serif SC，辅助标注Noto Sans SC；不依赖字体CDN。跨机器仍需渲染复核 |
| 配色 | 深蓝#102745，强调#255da8，辅助#65748a，浅底#eaf0f7；状态不能仅靠颜色区分 |
| 版心 | 正文左右约96–126px；标题约40–46px，正文约24–27px，来源约17–20px；具体取assets/report.css，不能靠缩字塞满 |
| 间距 | 细分隔线、对齐与必要留白；可视分析双栏间距约44px；主题与正文、页底与引用须不重叠 |
| 封面 | 可用目录与深蓝变量侧栏，指标从证据绑定；最终目录反映当期主线，不要求固定六章 |
| 引用 | 页脚用去重短来源与可展开完整定位，详细主张/摘录留Markdown和审计；长来源名/多定位不挤占正文 |
| 交互 | 翻页/方向键、滚轮/滑动；E编辑，Ctrl+S另存HTML；PDF按钮调用打印。编辑后同步JSON再核验 |

## 继承与改进

继承：证据与解释并列、细线高密度布局、市场与经营对照、可修正观点和未来验证点。

改进：不继承固定篇幅与公司池，不把原作者判断当标准答案；避免小字、长来源挤压、图表标签越界、控件遮挡、重复和稀疏单页。规范与模板可基于本期研究继续改进，参考稿不设质量上限。

首次风格分析可记录原件页码作为设计依据；日常正文与审计不把“本期又看了多少参考页”当成研究成果。具体图形、数据合同与验收操作分别在visual-storytelling.md和data-contract.md，不在本文件复制。
